# LBRY SDK NG 0.114.0rc1

This community-maintained release candidate moves the SDK to CPython 3.13.
It is maintained independently of LBRY Inc. The Python package remains `lbry`
and the command remains `lbrynet`.

## Installation changes

- Use a fresh 64-bit Python 3.13 environment. Supported CI targets are Linux
  x86-64, Windows x64 and Intel macOS 15 or later. Python 3.14 and Apple Silicon
  are not release targets for this candidate.
- The runtime and build dependencies have been updated, including aiohttp,
  cryptography, coincurve, protobuf, libtorrent and PyInstaller. Intel macOS
  builds cryptography from source and needs Rust, Xcode tools and Homebrew
  OpenSSL; see [INSTALL.md](../../INSTALL.md).
- The Linux-only `hub` extra selects Hub NG 1.1.0rc1 and the hash-pinned
  `lbry-rocksdb-ng` 0.8.3 CPython 3.13 wheel. It requires x86-64 and glibc 2.35+.
  Do not install the old and maintained RocksDB packages in the same environment.

## Compatibility and fixes

- Preserve deterministic seeded coin selection after Python removed the old
  shuffle callback. Existing wallet encryption, derivation, signatures and
  transaction serialization are covered by the wallet suites.
- Update removed asyncio APIs, torrent event ownership and cancellation cleanup.
  Close blob connections on late responses to cancelled requests and handle
  download timeouts before generic OS errors.
- Regenerate protobuf modules from checked-in schemas without changing the
  deployed wire definitions. Captured legacy descriptors and serialized messages
  check exact round trips, including unknown fields and historical signed claims.
- Keep the numeric wallet protocol version at `0.113.0`: the candidate suffix
  describes the SDK release and is not a protocol change.
- Replace the Hub's private OpenSSL-memory hashing dependency with a portable
  state implementation. Existing 120-byte saved states and database rollback
  retain their exact bytes. The RocksDB storage engine remains 6.25.3.
- Update SDK containers to Python 3.13. Retire the obsolete wallet-server and
  Torba container/deployment recipes; use Hub NG and the isolated SDK test runner.

## Validation and limits

The candidate is under validation in [SDK PR #20](https://github.com/kodxana/lbry-sdk-ng/pull/20)
and [Hub PR #9](https://github.com/kodxana/lbry-hub-ng/pull/9). Release publication
requires the complete workflow described in [releasing.md](../releasing.md).

Tests use temporary wallets and regtest chains with no real funds. No mainnet
wallet or full-size Hub snapshot has been exercised. Keep wallet backups and
the previous environment when evaluating the candidate. This is a prerelease,
not a claim that all inherited upstream issues are resolved.
